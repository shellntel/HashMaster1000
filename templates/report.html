Third-Party API Connection

You are about to connect to the Have I Been Pwned API, an external third-party service operated by Troy Hunt.

What data is sent?

  • Only the first 5 characters of each NTLM hash (k-Anonymity model)
  • Full hashes are never transmitted
  • Passwords are never transmitted
  • Usernames are never transmitted

How it works:

The API returns all hash suffixes matching your prefix. Your browser then checks locally for matches, ensuring your actual data never leaves your network.

About HIBP:

Have I Been Pwned is a free service created by security researcher Troy Hunt. It maintains a database of over 800 million passwords from known data breaches.

Kerberoast analysis requires ADD JSON input with Service Principal Names (SPNs).

This analysis is only available when using the Active Directory Dumper (ADD) JSON format.

Analysis of service accounts vulnerable to Kerberoasting attacks. Accounts with Service Principal Names (SPNs) can have their Kerberos tickets requested by any authenticated user for offline password cracking.

Risk Scoring: Each account is scored based on factors including: privilege level (adminCount), password age, encryption types supported, delegation configuration, and whether the password was cracked or found in breaches.

AS-REP Exposure Analysis

AS-REP analysis requires ADD JSON input with accounts that have Kerberos pre-authentication disabled (DONT_REQUIRE_PREAUTH).

This analysis is only available when using the Active Directory Dumper (ADD) JSON format.

✓

No AS-REP Roastable Accounts Found

Good news! None of the 0 accounts analyzed have Kerberos pre-authentication disabled.

What was checked:

  • Scanned all user accounts for the DONT_REQUIRE_PREAUTH flag (UAC bit 0x400000)
  • This flag, when set, allows attackers to request AS-REP tickets without authentication
  • Such tickets can be cracked offline to recover account passwords

Continue monitoring for accounts with pre-authentication disabled, especially legacy applications or service accounts that may be configured this way.

Analysis of accounts vulnerable to AS-REP roasting attacks. Accounts with Kerberos pre-authentication disabled can have their AS-REP tickets requested by anyone for offline password cracking without authentication.

Risk Scoring: Each account is scored based on: privilege level (adminCount), service account status, password exposure (cracked, HIBP, reused), activity recency, and password staleness as an exposure amplifier.
